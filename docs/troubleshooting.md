# Якщо щось не працює

Спочатку спробуйте найпростіше:

1. Переконайтеся, що **Docker Desktop запущений** (іконка кита біля годинника на Windows або у верхньому меню на Mac).
2. Запустіть **`stop`**, а потім знову **`start`**.
3. Перезавантажте комп'ютер і знову запустіть **`start`**.

Не допомогло? Запустіть **`diagnostics`** (`Windows\diagnostics.bat` або `Mac/diagnostics.command`).
Він створить файл `diagnostics.txt` у папці проєкту — надішліть його викладачу разом з описом проблеми.
Паролі та токени у цьому файлі автоматично приховані.

## Встановлення Docker

### «Virtualization support not detected» / «Віртуалізацію не виявлено» (Windows)

Docker потрібна апаратна віртуалізація процесора. Перевірте, чи вона увімкнена:
**Ctrl + Shift + Esc** → вкладка **Продуктивність** (Performance) → **ЦП** (CPU) → рядок **Віртуалізація** (Virtualization).

Якщо там «Вимкнуто» (Disabled) — її треба увімкнути в BIOS/UEFI комп'ютера. Назва пункту залежить від виробника:
*Intel Virtualization Technology*, *Intel VT-x*, *AMD-V*, *SVM Mode*. Знайдіть в інтернеті «як увімкнути віртуалізацію» + модель
вашого ноутбука або зверніться до викладача.

### «WSL needs updating» / «WSL 2 installation is incomplete» (Windows)

Відкрийте PowerShell **від імені адміністратора** (клік правою кнопкою на «Пуск» → «Термінал (адміністратор)»)
і виконайте:

```powershell
wsl --update
```

Після цього перезавантажте комп'ютер.

### Docker Desktop довго показує «Starting the Docker Engine…»

Зачекайте 2–3 хвилини. Якщо не допомогло — перезавантажте комп'ютер.
На Windows також допомагає `wsl --update` (див. вище).

### Mac: «Docker.app пошкоджено» або не відкривається

Переконайтеся, що завантажили версію для свого процесора: **Apple Silicon** (M1/M2/M3/M4) чи **Intel**
(меню Apple — значок яблука вгорі ліворуч → «Про цей Mac» → рядок «Чип» або «Процесор»).

## Запуск

### Вікно скрипта відкрилося і одразу закрилося (Windows)

Найімовірніше, ви запустили файл прямо з ZIP-архіву. Спочатку розпакуйте архів
(клік правою кнопкою на ZIP → «Видобути все…»), а потім запускайте `start.bat` з розпакованої папки.

### «Windows захистила ваш комп'ютер» (Windows SmartScreen)

Натисніть **«Докладніше»** (More info) → **«Виконати в будь-якому разі»** (Run anyway).
Щоб попередження не з'являлось: видаліть розпаковану папку, клікніть правою кнопкою на ZIP-файл → **Властивості** →
поставте галочку **«Розблокувати»** (Unblock) → **OK**, і розпакуйте ZIP знову.

### Mac: «Не вдалося перевірити "start.command"…» / «від неідентифікованого розробника»

Запустіть скрипт через Термінал (так macOS не блокує файл):

1. Відкрийте **Термінал**: натисніть **Cmd + Пробіл**, введіть `Terminal`, натисніть **Enter**.
2. Надрукуйте `bash ` (слово bash і пробіл), але **не натискайте Enter**.
3. Перетягніть мишкою файл `start.command` з Finder у вікно Терміналу.
4. Натисніть **Enter**.

Після першого такого запуску всі файли `.command` у цій папці відкриватимуться звичайним подвійним кліком.

### «toomanyrequests: You have reached your pull rate limit»

Docker Hub обмежує кількість завантажень без входу в акаунт (особливо коли багато людей в одній мережі, наприклад
у навчальному класі). Варіанти:

* зачекайте годину і запустіть `start` знову;
* або створіть безкоштовний акаунт на [hub.docker.com](https://hub.docker.com/signup), увійдіть у нього в Docker Desktop
  (кнопка **Sign in** угорі праворуч) і запустіть `start` знову.

### «port is already allocated» / «address already in use»

Якась інша програма на комп'ютері вже використовує порт 3000, 5678 або 4040. Закрийте програми для розробки,
які можуть його займати (інші проєкти Docker, локальні сервери), або перезавантажте комп'ютер.

### «Не вдалося запустити всі програми» / «container … is unhealthy»

* Перший запуск на повільному комп'ютері може тривати довше — просто запустіть `start` ще раз.
* Перевірте, чи вистачає пам'яті: закрийте зайві програми та вкладки браузера.
  Для роботи потрібно щонайменше 8 ГБ оперативної пам'яті на комп'ютері.
* Перевірте вільне місце на диску (потрібно щонайменше 10 ГБ).

### «На комп'ютері вже є дані … але немає файлу .env»

Ви, ймовірно, завантажили проєкт заново в іншу папку. Скопіюйте файл `.env` зі старої папки проєкту в нову і
запустіть `start` знову. Якщо старої папки немає і дані не потрібні — запустіть `reset`, а потім `start`.

> На Windows файл `.env` видно в провіднику. На Mac файли з крапкою на початку приховані — натисніть
> **Cmd + Shift + .** (крапка) у Finder, щоб їх показати.

## ngrok

### «Тунель ngrok не запрацював»

Скрипт покаже останні повідомлення ngrok. Найчастіші:

| Повідомлення | Що означає | Що робити |
|---|---|---|
| `ERR_NGROK_105`, `ERR_NGROK_107`, `authentication failed` | Неправильний токен | Скопіюйте токен ще раз з [dashboard.ngrok.com/get-started/your-authtoken](https://dashboard.ngrok.com/get-started/your-authtoken) |
| `ERR_NGROK_320`, `ERR_NGROK_319`, `ERR_NGROK_313` | Неправильний домен (чужий або не ваш безкоштовний) | Скопіюйте домен зі сторінки [dashboard.ngrok.com/domains](https://dashboard.ngrok.com/domains) |
| `ERR_NGROK_334` (`already online`), `ERR_NGROK_108` | Цей самий тунель уже запущений деінде | Зупиніть ngrok на іншому комп'ютері або в іншій програмі |
| `ERR_NGROK_123`, `ERR_NGROK_382` (`email address is verified`) | Не підтверджена пошта | Підтвердіть email за посиланням з листа від ngrok |

Коли скрипт запитає «Ввести дані ngrok ще раз?», введіть `т` і вставте правильні дані.

### Відкриваю адресу ngrok у браузері, а там попередження «You are about to visit…»

Це нормально для безкоштовного тарифу ngrok: таку сторінку бачать лише люди в браузері. Натисніть **Visit Site**.
Сервіси, які надсилають вебхуки (Telegram, Twenty тощо), цієї сторінки не бачать.

### Вебхук із зовнішнього сервісу не приходить

1. Workflow у n8n має бути **опублікований** (кнопка **Publish**) — інакше працює лише тестова адреса
   (*Test URL*) і лише поки натиснута кнопка **Listen for test event**.
2. Перевірте, що в зовнішньому сервісі вказана адреса **Production URL** з вузла Webhook.
3. Відкрийте [http://localhost:4040](http://localhost:4040) — там видно всі запити, що прийшли через тунель.

## Twenty CRM та n8n

### Twenty: «Please enter a valid URL» при створенні вебхука

Адреса має містити крапку в назві хоста. Використовуйте `http://n8n.internal:5678/webhook/...`
(не `http://n8n:5678/...` і не `http://localhost:5678/...`).

### Twenty → n8n: вебхук не спрацьовує

* Workflow у n8n має бути **опублікований** (Publish).
* Адреса у Twenty має починатися з `http://n8n.internal:5678/webhook/` (або бути адресою ngrok), а шлях після
  `/webhook/` — збігатися з полем **Path** у вузлі Webhook.

### n8n → Twenty: «ECONNREFUSED» або «connection refused»

У вузлі HTTP Request вказано `localhost`. Усередині Docker «localhost» — це сам контейнер n8n, а не ваш комп'ютер.
Використовуйте адресу `http://twenty.internal:3000/rest/...`.

### n8n → Twenty: помилка 401 / «Unauthorized»

API-ключ неправильний, протермінований або видалений. Створіть новий ключ у Twenty
(<http://localhost:3000/settings/developers/apis/new>) і вставте його в облікові дані *Bearer Auth* у n8n.

### Забув пароль від n8n або Twenty

Дані зберігаються лише на вашому комп'ютері. Найпростіше — почати з нуля: запустіть `reset`, а потім `start`
(усі дані буде видалено).
