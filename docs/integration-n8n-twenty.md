# Приклад: зв'язуємо n8n і Twenty CRM

У цьому прикладі ви налаштуєте зв'язок в обидва боки:

* **Частина 1. Twenty → n8n.** Коли в CRM з'являється новий контакт, Twenty одразу повідомляє про це n8n (через **вебхук**).
* **Частина 2. n8n → Twenty.** n8n сам створює контакт у CRM (через **API**).

> **Вебхук** — це адреса, на яку один сервіс автоматично надсилає повідомлення, коли щось сталося
> («з'явився новий контакт»). **API** — це «вхідні двері» програми для інших програм: через них n8n може
> читати й змінювати дані в Twenty.

Готові workflow лежать у папці проєкту `examples/n8n/`.

**Перед початком:** система запущена (`start`), ви зареєстровані в Twenty і n8n (див. [README](../README.md), Крок 5).

Twenty може показувати меню англійською або українською (залежить від мови браузера).
Нижче назви кнопок наведено англійською, а в дужках — українською.

---

## Як програми знаходять одна одну

Кожна програма працює у своєму «контейнері». Для браузера на вашому комп'ютері вони доступні через `localhost`,
а одна для одної — через спеціальні внутрішні адреси:

| Хто звертається | До кого | Адреса |
|---|---|---|
| Ваш браузер | Twenty | `http://localhost:3000` |
| Ваш браузер | n8n | `http://localhost:5678` |
| Twenty (вебхук) | n8n | `http://n8n.internal:5678/webhook/…` |
| n8n (вузол HTTP Request) | Twenty | `http://twenty.internal:3000/rest/…` |
| Сервіси з інтернету (Telegram, форми тощо) | n8n | `https://<ваш-домен>.ngrok-free.app/webhook/…` |

> **Чому не `localhost`?** Усередині контейнера `localhost` означає «я сам». Якщо n8n звернеться до
> `localhost:3000`, він шукатиме Twenty всередині себе і не знайде.

## Частина 1. Twenty → n8n: новий контакт

### 1.1. Імпортуйте workflow у n8n

1. Відкрийте n8n: <http://localhost:5678>.
2. Натисніть **Create workflow** (створити workflow).
3. У правому верхньому куті натисніть **⋯** (три крапки) → **Import** → **From file**.
4. Виберіть файл `examples/n8n/01-twenty-to-n8n-new-person.json` з папки проєкту.

З'являться два вузли:

* **Вебхук від Twenty** — «слухає» адресу, на яку Twenty надсилатиме повідомлення;
* **Дані контакту** — витягує з повідомлення ім'я, прізвище, email і посаду.

> Інший спосіб імпорту: відкрийте JSON-файл у Блокноті (Windows) чи TextEdit (Mac), скопіюйте весь текст
> (**Ctrl+A**, **Ctrl+C** / **Cmd+A**, **Cmd+C**) і вставте прямо на порожнє полотно n8n (**Ctrl+V** / **Cmd+V**).

### 1.2. Опублікуйте workflow

1. Натисніть **Save** (або **Ctrl+S** / **Cmd+S**).
2. Натисніть **Publish** угорі праворуч.

Поки workflow не опублікований, вебхук не працює.

### 1.3. Створіть вебхук у Twenty

1. Відкрийте у Twenty **Settings** (Налаштування) → **Developers** (Розробники) → вкладка **Webhooks**
   і натисніть **Create webhook** (Створити Webhook).
   Або просто перейдіть за посиланням: <http://localhost:3000/settings/developers/webhooks/new>
2. У полі **Endpoint URL** вставте:

   ```text
   http://n8n.internal:5678/webhook/twenty-new-person
   ```

3. У розділі **Filters** (Фільтри) виберіть об'єкт **People** (Люди) і дію **Created** (створено).
4. Натисніть **Save** (Зберегти) угорі праворуч.

> Остання частина адреси (`twenty-new-person`) має збігатися з полем **Path** у вузлі «Вебхук від Twenty».
> Для власних вебхуків використовуйте той самий формат: `http://n8n.internal:5678/webhook/<path>`.

### 1.4. Перевірте

1. У Twenty відкрийте **People** (Люди) і додайте новий контакт (кнопка **+** / **Add New**): вкажіть ім'я, прізвище та email.
2. У n8n відкрийте свій workflow → вкладка **Executions** (угорі по центру).
3. Ви побачите новий запуск. Клікніть на нього, а потім на вузол **Дані контакту** — там будуть дані щойно створеного контакту.

Що надсилає Twenty (скорочено):

```json
{
  "eventName": "person.created",
  "objectMetadata": { "nameSingular": "person" },
  "record": {
    "id": "8d4117b6-…",
    "name": { "firstName": "Олена", "lastName": "Коваль" },
    "emails": { "primaryEmail": "olena.koval@example.com" },
    "jobTitle": "Маркетологиня"
  }
}
```

У n8n ці дані доступні у виразах, наприклад: `{{ $json.body.record.name.firstName }}`.

> Якщо в цей момент n8n був вимкнений, повідомлення від Twenty загубиться — Twenty не надсилає його повторно.

## Частина 2. n8n → Twenty: створюємо контакт

### 2.1. Створіть API-ключ у Twenty

1. Відкрийте у Twenty **Settings** (Налаштування) → **Developers** (Розробники) → вкладка **API**
   і натисніть **Create API key** (Створити ключ API).
   Або просто перейдіть за посиланням: <http://localhost:3000/settings/developers/apis/new>
2. Заповніть:
   * **Name** — наприклад, `n8n`;
   * **Role** — **Admin** (повний доступ; для навчання так найпростіше);
   * **Expiration Date** — наприклад, **Never** (Ніколи) або **1 year**.
3. Натисніть **Save** (Зберегти).
4. **Одразу скопіюйте ключ** (довгий рядок, що починається з `eyJ…`). Twenty показує його лише один раз!

> API-ключ — це як пароль. Не надсилайте його нікому й не публікуйте.

### 2.2. Імпортуйте workflow у n8n

Так само, як у кроці 1.1, створіть новий workflow і імпортуйте файл
`examples/n8n/02-n8n-to-twenty-create-person.json`.

Вузли:

* **Запуск вручну** — workflow запускається кнопкою;
* **Дані нового контакту** — ім'я, прізвище, email і посада (змініть на свої);
* **Створити контакт у Twenty** — надсилає запит `POST http://twenty.internal:3000/rest/people`.

### 2.3. Підключіть API-ключ

1. Двічі клікніть на вузол **Створити контакт у Twenty**.
2. У полі **Credential for Bearer Auth** виберіть **Create new credential**.
3. У поле **Bearer Token** вставте API-ключ з кроку 2.1.
4. Натисніть **Save** і закрийте вікно облікових даних, а потім і вікно вузла.

> **Credentials** (облікові дані) — це місце, де n8n надійно (у зашифрованому вигляді) зберігає паролі та ключі.
> Їх створюють один раз і потім вибирають у будь-якому вузлі.

### 2.4. Запустіть

1. Натисніть **Execute workflow** внизу полотна.
2. Усі вузли мають позначитися зеленими галочками.
3. Відкрийте Twenty → **People** (Люди): там з'явилася **Олена Петренко**.

Якщо workflow з Частини 1 опублікований, створення цього контакту одразу запустить і його — загляньте
в **Executions** першого workflow. Так виглядає повний цикл: n8n → Twenty → n8n.

### Що далі

* Повний список можливостей API Twenty: **Settings → Developers → API → Documentation** — там є інтерактивна
  документація (REST і GraphQL), де можна спробувати запити.
* Змінюйте поля у вузлі **Дані нового контакту** або підставте дані з іншого вузла (наприклад, з форми чи Telegram).

## Додатково: база даних для власних вправ

У системі є окрема база PostgreSQL **practice** — у ній можна створювати свої таблиці (наприклад, з вузла
**Postgres** у n8n), не ризикуючи зламати n8n чи Twenty.

Створіть у n8n облікові дані **Postgres** з такими значеннями:

| Поле | Значення |
|---|---|
| Host | `postgres` |
| Database | `practice` |
| User | `student` |
| Password | `student` |
| Port | `5432` |
| SSL | `Disable` |

> Бази `twenty` і `n8n` у тій самій PostgreSQL — службові. Не змінюйте їх напряму: з даними Twenty працюйте
> через API (як у Частині 2).
